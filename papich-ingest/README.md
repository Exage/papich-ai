# Papich Ingest — локальная база знаний из YouTube

CLI для macOS Apple Silicon: ссылки → аудио → русская транскрипция с таймкодами → чанки → локальный поиск. Это подготовка базы для будущего RAG, без чатбота, UI, сервера и Docker. Платных API и облачного inference нет. Интернет нужен для видео и первого скачивания бесплатных весов; текст и аудио обрабатываются на Mac.

Выбранный стек: `yt-dlp` + `ffmpeg`, `mlx-whisper` на Metal, `sentence-transformers` с `intfloat/multilingual-e5-small`, Qdrant local mode, SQLite. `small` у Whisper — разумный старт для русского; E5-small экономит память на M1 8 GB. `multilingual-e5-base` можно выбрать в конфигурации для отдельной базы. Используются dataclasses и обычные dict, без дополнительного слоя моделей.

## Установка на Mac mini M1

Рекомендуется актуальная macOS, нативный arm64 Python **3.11**, без Rosetta. Код требует Python 3.11+; для воспроизводимого окружения начинайте с 3.11, поскольку доступность ML-библиотек для новых Python зависит от wheel-пакетов. На старой macOS pip может подобрать более старые совместимые версии MLX/PyTorch; их сочетание отдельно не проверено.

```bash
brew install ffmpeg python@3.11 deno
cd /путь/к/papich-ingest
/opt/homebrew/bin/python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -c 'import platform; print(platform.machine())'
```

Последняя команда должна вывести `arm64`. Deno и установленный через `yt-dlp[default]` пакет EJS нужны для современных YouTube JS challenges. [Документация yt-dlp](https://github.com/yt-dlp/yt-dlp#dependencies).

`requirements.txt` ограничивает основные несовместимые обновления; `requirements-tested.txt` фиксирует полное окружение проверки на Apple Silicon. Для повторения именно его вместо обычного файла установите `pip install -r requirements-tested.txt`. yt-dlp иногда необходимо обновлять отдельно вслед за YouTube.

## Первый запуск

Создайте `urls.txt`, вставив 2–3 **настоящие ссылки**, по одной на строке (без Markdown-скобок). Пустые строки и строки с `#` игнорируются. Пример формы файла:

```text
https://www.youtube.com/watch?v=VIDEO_ID_01
https://youtu.be/VIDEO_ID_02
https://www.youtube.com/shorts/VIDEO_ID_03
```

`VIDEO_ID_01` и остальные — placeholders, замените их своими идентификаторами.

```bash
python ingest.py urls.txt
python search.py "деньги"
python search.py "что он говорил про работу" --top-k 5
```

Сначала будут скачаны веса Whisper и E5 с Hugging Face (для стандартного режима аккаунт не нужен). Это может занять несколько минут. Веса остаются в стандартном HF cache. Для размещения кэша внутри проекта: `export HF_HOME="$PWD/data/model-cache"` перед запуском.

В терминале и `data/logs/ingest.log` видны этапы `Downloading`, `Transcribing`, `Chunking`, `Embedding`, `Saved`, а также номер видео, ASR-блока и число обработанных чанков. Включены retries yt-dlp. При ошибке одного видео обработка остальных продолжается. Код выхода: `0` — без ошибок, `1` — одна или несколько ошибок, `130` — Ctrl+C.

## CLI

```bash
python ingest.py --url "https://youtu.be/VIDEO_ID_01"
python ingest.py urls.txt --model small
python ingest.py urls.txt --force
python ingest.py urls.txt --skip-embeddings
# Позже добавить векторы, сохранив уже готовую транскрипцию:
python ingest.py urls.txt
python ingest.py --url "https://www.youtube.com/playlist?list=PLAYLIST_ID" --playlist
python ingest.py urls.txt --config config.yaml
python search.py "деньги" --top-k 10 --json
```

`--url` можно повторять и сочетать с файлом. Ссылка на видео с `&list=...` означает только это видео, пока не передан `--playlist`. Чистый playlist требует `--playlist`. Повторяющиеся идентификаторы внутри очереди обрабатываются один раз даже с `--force`. Live и upcoming broadcasts отклоняются; сохранённые записи стримов поддерживаются. Недоступные записи плейлиста обрабатываются по ID, если YouTube его раскрывает; скрытые записи без ID попадают в предупреждения.

## Хранение

```text
data/
  audio/<video_id>/source.webm       # формат зависит от YouTube, только аудио
  audio/<video_id>/normalized.wav    # mono, PCM16, 16 kHz
  transcripts/<video_id>.raw.json   # исходные ASR-сегменты и confidence-поля
  transcripts/<video_id>.parts/     # исходные результаты каждого блока и checksum
  transcripts/<video_id>.json       # очищенные сегменты + video metadata
  transcripts/<video_id>.speakers.json  # только при включённой диаризации
  chunks/<video_id>.jsonl
  db/metadata.sqlite
  db/vectors/                      # постоянное хранилище Qdrant
  logs/ingest.log
```

Метаданные содержат ID, title, channel/uploader, canonical URL, original URL, upload_date и duration. Raw JSON хранит глобальные таймкоды; `.parts/*.raw.json` также сохраняют полный исходный результат блока с локальными таймкодами и offset. Файлы JSON заменяются атомарно, их SHA-256 записываются в SQLite. WAV после полностью успешной индексации удаляется по умолчанию; raw, чанки и контрольные точки сохраняются. При `--skip-embeddings` аудио пока сохраняется.

В чанке находятся `id`, `video_id`, `title`, `channel`, `upload_date`, `source_url`, `original_url`, `timestamp_url`, `start/end`, `speaker`, `speakers`, `text`, `chunk_index`, `token_count`, `duplicate_of`, `duplicate_score`. Все поля сохранены и в Qdrant payload. Qdrant использует стабильный UUID, полученный из читаемого chunk ID; сам ID остаётся в payload.

## Чанки и качество текста

Чанки собираются из соседних speech segments по времени. Цель — до 450 слов, но действует **реальный токеновый предел 480** вместе с `passage: ` и special tokens. У E5 контекст 512 токенов, поэтому 300–700 русских слов часто не помещаются; фактические чанки будут короче. Ничего не обрезается молча при embedding. Overlap — хвост из целых сегментов в пределах 64 токенов; если последний сегмент крупнее overlap, пересечения на этой границе нет. Очень длинный отдельный сегмент делится по словам, сохраняя его исходные временные границы (не выдуманные word timestamps).

Очищение нормализует пробелы, убирает пустые/нулевые сегменты, точные дубли с теми же таймкодами, объединяет очень короткий предыдущий сегмент с тем же speaker через паузу до 0.5 сек. Настоящие повторы речи на разных таймкодах сохраняются. Распознавание не превращается в пересказ. Повторяющиеся hallucinations на разных таймкодах намеренно не удаляются автоматически: уверенно отличить их от речи нельзя. Raw всегда доступен для проверки.

Пустая речь сохраняется как пустая транскрипция, видео завершается без векторов. Whisper может ошибаться на музыке, тишине, игровых именах, перекрывающихся голосах; низкое качество не маскируется оценкой «уверенности». `no_speech_prob`, `avg_logprob` и другие доступные поля остаются в raw.

E5 получает `passage: текст` при индексации и `query: запрос` при поиске, векторы нормализуются. Поиск возвращает cosine similarity, а не вероятность правильного ответа. [Описание модели E5](https://huggingface.co/intfloat/multilingual-e5-small).

## Повторы, стадии и восстановление

SQLite хранит `status`, `last_success`, `indexed`, ошибку, fingerprints конфигурации и checksums артефактов. Стадии: `discovered → downloaded → transcribed → chunked → embedded → completed`. `failed` сохраняет последнюю успешную стадию. Таблица `errors` хранит историю ошибок, включая ссылки, для которых метаданные недоступны.

Повторите ту же команду после сбоя. Готовые видео пропускаются без запроса метаданных в сеть, если конфигурация, JSON и число векторов согласованы. Чанки повреждены — перестроятся из raw; повреждён raw — транскрипция восстановится из проверенных блоков; повреждено аудио — оно скачивается заново. После сбоя во время embeddings готовый transcript/chunks сохраняется; векторы **этого видео** пересчитываются целиком идемпотентно. Во время ASR контрольная точка записывается каждые 600 секунд: после аварии повторяется незавершённый блок. Метки времени на границах этих блоков могут быть менее точными из-за обрыва фразы; размер регулируется.

`--force` заново скачивает аудио, удаляет ASR checkpoints для указанных видео, заменяет их чанки и векторы, включая устаревшие хвостовые chunk ID. Остальные видео сохраняются. Поиск учитывает только завершённые видео: частично записанные векторы после сбоя не показываются. Один процесс работает с базой одновременно; конкурентный запуск выдаёт понятную ошибку. Не запускайте поиск параллельно ingestion.

Изменение Whisper или параметров чанков автоматически инвалидирует соответствующие стадии для переданных видео. Изменение **embedding model или query/passage prefixes** требует новой `data_dir`: смешивать вектора разных моделей в одной коллекции запрещено даже при совпадении размерности. Не редактируйте уже записанные JSON вручную: checksums воспримут это как повреждение.

Текстовая дедупликация нормализует регистр/пунктуацию и сравнивает множества трёхсловных шинглов (Jaccard). Порог `0.92`; точное совпадение — `1.0`. Работает внутри видео и между видео. Совпадения получают `duplicate_of` и `duplicate_score`, **ничего не удаляется**. Это подсказка для проверки, не доказательство общего происхождения. Метки отражают состояние корпуса на момент добавления: при изменении старого видео ссылка может стать устаревшей. Для большого корпуса потребуется индекс кандидатов; текущая реализация последовательно сканирует тексты в SQLite и может стать медленной.

## Память и модели на M1

Whisper и embeddings не держатся одновременно: ASR, optional diarization, токенизация и embedding запускаются отдельными последовательными процессами. Выход процесса освобождает кеши модели, включая MLX. ASR загружает в память только один 10-минутный WAV-блок, а модель переиспользуется между блоками одного видео. Параллельной транскрипции нет. CPU выбран для E5 по умолчанию ради предсказуемого расхода памяти; можно попробовать `embedding_device: mps` с `embedding_batch_size: 4`.

Ориентировочный бюджет процесса (не измерение на вашем M1, зависит от macOS и версий библиотек):

| Конфигурация | Планируемая RAM | Применение |
|---|---:|---|
| Whisper tiny/base | около 1–2 GB | Проверка установки, ниже качество русского |
| Whisper small | около 2–4 GB | Начальный выбор для 8 GB |
| Whisper medium | около 4–6 GB и более | Лучше пробовать на 16 GB |
| Whisper large-v3/turbo | зависит от модели, несколько GB+ | Не стартовый вариант для 8 GB |
| E5-small CPU, batch 8 | около 1–2 GB | По умолчанию |
| E5-base CPU | около 2–3 GB | Больше RAM, отдельная база |

Это память процесса, дополнительно нужна память macOS. Закройте тяжёлые приложения. Скорость не обещается: зависит от длины, качества записи и модели. Для смены модели: `--model tiny`, `base`, `small`, `medium`, `large-v3`, `turbo` или путь к MLX-модели/ID HF repo. Используйте мультиязычные модели, не `.en`. [MLX Whisper](https://github.com/ml-explore/mlx-examples/tree/main/whisper).

WAV занимает около 115 MB/час, рядом временно хранится сжатое исходное аудио. Очень длинные записи требуют свободного места; места для модели и всех видео также должно хватать. Qdrant local mode загружает индекс в память: для сотен тысяч/миллионов чанков понадобится другая стратегия хранения. MVP рассчитан на личную коллекцию.

## Optional diarization

Выключена по умолчанию: `pyannote.audio` тяжёлая, модель gated. Реализован бесплатный **локальный** адаптер community-1, а не платный hosted endpoint. Установка отдельно:

```bash
source .venv/bin/activate
pip install -r requirements-diarization.txt
```

1. Откройте [community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), войдите в бесплатный Hugging Face аккаунт и примите условия скачивания модели.
2. Создайте read token с доступом к этому gated repo. В терминале: `read -s HF_TOKEN`, вставьте токен, затем `export HF_TOKEN`. Токен нужен для скачивания, не для платного inference; не сохраняйте его в проекте.
3. В `config.yaml`: `diarization_enabled: true`.
4. Запустите `python ingest.py urls.txt`. Raw Whisper переиспользуется; если аудио уже удалено, оно скачается ещё раз.

Модель работает на CPU. Разметка сохраняется отдельно; speaker для ASR-сегмента выбирается по максимальному времени пересечения. Это приблизительное сопоставление, особенно при смене говорящего внутри сегмента. `speaker_0`, `speaker_1` обозначают анонимных говорящих **только внутри одного видео**; одинаковая метка в разных видео не означает одного человека. Чанк с несколькими говорящими имеет `speaker: null` и список `speakers`. Определение конкретного человека не реализовано.

Диаризация обрабатывает всю запись целиком и не обладает такой же экономией памяти, как блочная ASR. Для многочасовых стримов на 8 GB оставьте её выключенной. Нужны свободная RAM и время. Этот необязательный путь требует отдельной проверки с вашим HF доступом; базовый pipeline от него не зависит. Для полностью offline запуска укажите путь к заранее скачанной модели в `diarization_model`.

## Диагностика

- `ffmpeg not found`: `brew install ffmpeg`; проверьте `which ffmpeg`.
- Ошибка Metal: используйте Terminal с нативным arm64 Python; sandbox/headless окружение может не предоставлять GPU.
- YouTube изменил extractor: `pip install -U 'yt-dlp[default]'`; проверьте `deno --version`.
- Age restriction/login/бот-проверка: публичная страница не гарантирует анонимное скачивание. Для видео, доступного вашему аккаунту, можно указать локальный Netscape cookiefile в `cookies_file`. Файл содержит сессию: храните вне репозитория. Инструмент не обходит недоступность удалённых/приватных видео.
- 403/429 и сетевые ошибки: повторите позже, ошибки сохранены. Пайплайн продолжает остальные ссылки.
- Ошибка HF: проверьте сеть, свободное место и модель. После первого скачивания можно использовать `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1` для локальных стадий; скачивание новых YouTube-видео всё равно требует сети.
- Плохой текст: просмотрите raw и таймкоды, попробуйте `--model medium` при достаточной RAM. Никакая локальная очистка не восстановит неверно распознанные слова надёжно.
- Пустой поиск: ingestion должен завершиться без `--skip-embeddings`. Подробности в `data/logs/ingest.log` и SQLite.

Проверить состояния:

```bash
sqlite3 data/db/metadata.sqlite 'SELECT id,status,last_success,error FROM videos;'
```

Начать полностью заново, сохранив резервную копию:

```bash
mv data "data.backup-$(date +%Y%m%d-%H%M%S)"
python ingest.py urls.txt
```

Удалить именно базу и обработанные результаты без резервной копии: после остановки ingestion/search выполните `rm -rf ./data` **из каталога проекта**, проверив путь. Стандартный HF cache вне data останется. Для пользовательских directories удаляйте соответствующие настроенные пути.

## Код и тесты

`src/downloader.py`, `audio.py`, `transcriber.py`, `diarization.py`, `cleaner.py`, `chunker.py`, `embeddings.py`, `vector_store.py`, `metadata_store.py`, `dedup.py`, `pipeline.py` разделяют стадии. `worker.py` изолирует память тяжёлых библиотек; `config.py`, `models.py`, `urls.py`, `utils.py` содержат общие функции. Все пути данных задаются в YAML. Относительные пути считаются от config.yaml/data_dir.

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты не скачивают видео/модели: URL/Shorts/live, timestamp links, границы и overlap чанков, отсутствие потери слов, oversize segments, SQLite transitions, checksum corruption, dedup, реальный Qdrant local roundtrip, повторный запуск, force, восстановление после сбоя embeddings и повреждённых JSON, продолжение после недоступного видео. Тяжёлые стадии в pipeline-тестах подменены маленькими фикстурами.

Отдельная реальная проверка русского ASR и тематического поиска: `python -m tests.manual_smoke`. Она использует macOS `say` с голосом Milena, Whisper small и настоящий E5/Qdrant. Скачивает веса, создаёт две синтетические записи в `/tmp` и проверяет, что запрос «деньги» находит финансовую тему раньше кулинарии. Подменена только загрузка YouTube; тестовые URL/ID обозначают синтетические фикстуры, не реальные видео. Результат и каталог печатаются в терминале. Не входит в обычный pytest.

Для будущего RAG используйте `semantic_search(query, config, top_k)` из `search.py` либо JSON-вывод CLI. Она возвращает релевантные чанки, cosine score и source metadata. LLM и UI подключаются отдельно; ingestion их не импортирует.
