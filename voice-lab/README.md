# Voice Lab

Локальный прототип: загрузка своего голоса → вопрос Gemma через Ollama → озвучка ответа.
Можно отдельно озвучить произвольный текст. Интерфейс на русском, без фронтенд-сборки.

## Запуск на этом Mac

Откройте Ollama, затем в терминале:

```bash
cd /Users/n.gorkavchuk/Desktop/papich-ai/voice-lab
bash run.command
```

Откройте http://127.0.0.1:8765. Остановка: Ctrl+C в терминале.

1. Загрузите WAV, M4A, MP3, FLAC или другой поддерживаемый аудиофайл до 30 МБ.
2. Выберите начало и длину чистого фрагмента (по умолчанию первые 15 секунд).
3. Нажмите «Сохранить голос» и прослушайте сохранённый фрагмент.
4. Выберите движок и нажмите «Озвучить». Первый запуск каждого движка скачивает его веса.
5. Перейдите в «Чат с Gemma», выберите установленную модель и задайте вопрос.

На странице по умолчанию выбран Chatterbox Multilingual V3. Доступны три движка:

| Движок | Реализация | Настройки |
| --- | --- | --- |
| Chatterbox Multilingual V3 | MLX, `mlx-community/chatterbox-multilingual-v3` | Русский `ru`, полный набор параметров генерации (см. ниже); текст образца не используется |
| Qwen3-TTS 1.7B | MLX, `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit` | Русский `russian`, необязательный точный текст образца |
| XTTS v2 | Coqui, отдельный Python-процесс, MPS при доступности | Русский `ru`, клонирование по аудио; без регулятора эмоций |

В памяти остаётся только один TTS-движок. Переключение выгружает предыдущий.
XTTS запускается отдельным процессом на каждый запрос, поэтому требует повторной
загрузки весов в память. Перед запуском пользователь должен ознакомиться с CPML и
подтвердить условия флажком в интерфейсе. Подтверждение не включено автоматически;
после принятия оно хранится локально в `data/xtts-license.json`.
Журнал ошибок XTTS: `data/xtts.log`.
Chatterbox использует первые 6–10 секунд образца для части голосовых признаков;
загрузка минутной записи не означает использование всей минуты всеми компонентами.

Для совместимости API без поля `engine` использует Qwen.
Русский язык задан явно. Для возврата к лёгкой модели перед запуском задайте
`VOICE_LAB_TTS_MODEL=mlx-community/Qwen3-TTS-12Hz-0.6B-Base-4bit`.

Расшифровка необязательна: без неё используется образец тембра. Для более точного
переноса манеры речи можно указать точный текст **только выбранного фрагмента**
в «Уточнить голос» перед сохранением либо в поле «Текст сохранённого образца» после
загрузки. Расшифровка включает ICL-режим. Для эмоций используйте отдельные образцы
с нужной подачей (например, «Мой голос — радостно») и их точными расшифровками.
У Base нет управления эмоциями через текстовую инструкцию `instruct`;
перенос эмоции из образца нужно оценивать на слух. Более крупная модель не
гарантирует улучшение конкретного голоса. Минутный исходник автоматически обрезается
до выбранных 3–120 секунд и преобразуется в моно PCM WAV 24 кГц.
Исходный загруженный файл после преобразования удаляется из временного хранилища;
оригинал на вашем компьютере остаётся без изменений.

### Параметры Chatterbox

Все параметры применяются к тестовой озвучке и к озвучке ответов Gemma. Настройки
сохраняются в `localStorage` и восстанавливаются после перезагрузки страницы.
Кнопка «Сбросить настройки» возвращает исходные значения.

| Параметр | По умолчанию | Диапазон | Описание |
| --- | --- | --- | --- |
| **Выразительность** (exaggeration) | 0.5 | 0…1 | Усиливает подачу, но не выбирает конкретную эмоцию. |
| **CFG** (cfg_weight) | 0.5 | 0…2 | Сила обусловливания при генерации; больше не обязательно лучше. |
| **Температура** (temperature) | 0.8 | 0.1…1.5 | Повышает вариативность; высокие значения могут снижать стабильность. |
| **Штраф за повторы** (repetition_penalty) | 1.2 | 1…2 | Помогает уменьшать повторы; чрезмерное значение может портить речь. |
| **Top-p** (top_p) | 1.0 | 0.01…1 | Отбирает варианты с накопленной вероятностью до порога. |
| **Min-p** (min_p) | 0.05 | 0…1 | Минимальный порог вероятности для отбора вариантов. |
| **Лимит токенов** (max_new_tokens) | 1500 | 100…3000 | Ограничивает длину генерации в токенах, не в секундах; маленький лимит может обрезать фразу. |
| **Язык** (lang_code) | ru | из списка | Код языка для мультиязычной модели. |
| **Seed** | авто | 0…4294967295 | Помогает сравнивать настройки в одинаковых условиях; побитовая повторяемость между устройствами и версиями не гарантируется. Пусто = автоматический выбор. |
| **Подробный журнал** (verbose) | false | — | Диагностический вывод в журнал сервера, не улучшение качества. |

**Ограничения MLX-реализации:** параметры `speed`, `voice`, `stream`, `streaming_interval` игнорируются моделью и не добавлены в интерфейс. Нет режимов «радость», «злость», «грусть» — выразительность усиливает подачу, но не задаёт конкретную эмоцию. Потоковой выдачи аудио нет — генерируется целый WAV.

## Установка с нуля

Нужен Mac с Apple Silicon, совместимая с MLX версия macOS, Python 3.11+, FFmpeg,
Ollama и установленная локальная модель. На этом Mac обнаружена `gemma4:e2b`.

```bash
brew install python@3.11 ffmpeg
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
python3.11 -m venv .venv-xtts
.venv-xtts/bin/pip install -r requirements-xtts.txt
bash run.command
```

Для повторения проверенного окружения используйте `requirements-tested.txt`, если он есть.
MLX использует GPU Apple Silicon. Модели отвечают локально; первоначальное скачивание
весов и библиотек требует интернета. Нет оплаты за запросы. Скорость и сходство
голоса зависят от записи и оборудования; это эксперимент, не гарантия точной копии.

## Структура и перенос

- `app.py` — HTTP API, обращение к Ollama, подготовка записи и фоновые задания.
- `voice_engine.py` — адаптер Qwen3-TTS через MLX Audio; заменяется независимо от UI.
- `static/` — страница, стили и JavaScript без сторонних CDN.
- `data/voices/` — сохранённые фрагменты и их метаданные.
- `data/outputs/` — созданные WAV-файлы.
- `data/models/` — скачанные веса; каталог исключён из Git.

Сервер слушает только `127.0.0.1`. Для встраивания в основной проект вызывайте API
через его бэкенд либо разместите UI под тем же origin. Это локальный прототип без
авторизации; перед публичным размещением нужны аутентификация, квоты и управление
хранением. Аудиофайлы сохраняются до ручного удаления; автоматической очистки нет.
История чата хранится в памяти страницы и сбрасывается при её перезагрузке.

### API

Документация: http://127.0.0.1:8765/docs

- `GET /api/status` — локальные модели Ollama, состояние TTS, занятость.
- `GET /api/voices` — сохранённые голоса.
- `POST /api/voices` — multipart: `file`, `name`, `start`, `seconds`, `transcript`.
- `PATCH /api/voices/{id}` — JSON: `transcript`, обновление текста сохранённого образца.
- `POST /api/chat` — JSON: `message`, `model`, `history` (до 20 сообщений).
  Возвращает `text`, `seconds`, `model`.
- `POST /api/tts/prepare` — JSON: `engine` (`qwen`, `chatterbox`, `xtts`),
  для XTTS также `xtts_license_accepted: true` после принятия лицензии пользователем.
  Предварительная загрузка TTS, возвращает job ID.
- `GET /api/tts/settings` — значения по умолчанию, границы и поддерживаемые языки Chatterbox.
- `POST /api/speech` — JSON: `text` (до 1500 символов), `voice` (ID голоса).
  Также принимает `engine`, `exaggeration` (0–1, только Chatterbox, для совместимости),
  `chatterbox` (объект с полными настройками Chatterbox, приоритет над `exaggeration`),
  `xtts_license_accepted` (только XTTS). Возвращает HTTP 202 и `{id, state, engine, engineName, settings?}`.
- `GET /api/jobs/{id}` — опрос задания. `done` содержит `audioUrl`, `seconds`, `duration`,
  `settings` (фактически применённые настройки Chatterbox с конкретным seed);
  `error` содержит сообщение об ошибке.
- `GET /api/audio/{id}` — готовый WAV.

Задания выполняются последовательно, повторный запрос при занятости даёт HTTP 409.
Генерация TTS работает в отдельном потоке, страница продолжает отвечать.
Gemma выгружается из памяти после ответа (`keep_alive: 0`), чтобы оставить память TTS.
Это может увеличить задержку следующего текстового ответа. Перезагрузка страницы
не отменяет уже запущенную генерацию; сведения о задании сохраняются до перезапуска
сервера (последние 100 заданий), файлы — на диске.

## Проверки

```bash
.venv/bin/pip install pytest
.venv/bin/python -m pytest tests -q
```

Тесты проверяют загрузку/обрезку, повреждённые файлы, валидацию, локальные запросы,
приоритет настроек Chatterbox, попадание параметров в адаптер, метаданные задания,
автоматический seed, отбраковку некорректных значений и неизвестных полей,
изоляцию настроек от Qwen/XTTS, освобождение очереди после ошибки.
Не скачивают модели и не проверяют качество речи.
